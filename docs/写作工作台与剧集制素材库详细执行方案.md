# 星河写作工作台与剧集制素材库详细执行方案

本文档基于《星河写作工作台详细方案与执行计划》进一步拆解，提供详细的验收清单、后端数据库表草案、API 草案以及完整的测试清单。

## 1. 写作工作台 W1-W7 详细验收清单

### W1：写作工作台壳子 (当前阶段)
- [ ] **入口与加载**：在主界面侧边栏或底部工具栏有“写作”入口，点击后懒加载（Lazy Load）写作工作台组件，不阻塞主画布。
- [ ] **三栏布局**：成功渲染左侧（项目/剧集树）、中间（编辑器区）、右侧（大纲/信息面板）的标准三栏 IDE 布局。
- [ ] **Mock 数据注入**：左侧树能正确加载并展示 Mock 的项目、季、集、场次列表。
- [ ] **交互响应**：点击左侧的集或场次，中间编辑器能切换到对应文本；顶栏按钮（保存、分屏、生成分镜等）存在且占位正常。

### W2：剧本解析器 (当前阶段)
- [ ] **基础解析**：将纯文本（Raw Text）输入解析为结构化的 `ScriptBlock` 数组。
- [ ] **场景识别**：准确识别“场景一”、“INT.”、“外景”等开头，提取时间（日/夜）、地点。
- [ ] **角色与对白识别**：准确识别单独一行的角色名，及其紧跟的对白内容。
- [ ] **动作描述**：未被识别为场景、角色、对白、转场的普通段落，正确归类为动作描述（Action）。
- [ ] **单元测试**：提供至少 5 种不同常见格式（中文标准、好莱坞格式、网文格式）的测试用例，解析准确率达到预期。

### W3：编辑器高亮和右侧大纲 (当前阶段)
- [ ] **实时高亮**：编辑器（TextArea + Overlay 或 CodeMirror）中，场景标题、角色名、对白、动作能显示不同颜色或字体样式。
- [ ] **防抖解析**：输入文本时，解析器具备防抖（Debounce）机制（如 300ms-500ms），不引起输入卡顿。
- [ ] **大纲联动**：右侧“大纲”Tab 实时更新当前剧本的场次列表；右侧“人物”Tab 实时统计当前集中出现的角色。
- [ ] **点击跳转**：点击右侧大纲的某一场次，编辑器能平滑滚动至对应文本行。

### W4：剧本版本保存与分屏对比 (当前阶段)
- [ ] **自动/手动保存**：支持停止输入一定时间后自动保存草稿；支持手动点击“保存版本”生成快照。
- [ ] **版本列表**：右侧“版本”Tab 能列出历史版本记录（含时间、标签）。
- [ ] **分屏模式**：点击“分屏对比”后，中间区域分为左右两栏，分别显示两个不同版本。
- [ ] **差异高亮（Diff）**：在分屏模式下，能以高亮背景（如绿色新增、红色删除）显示两个版本的文本差异。

### W5：导演分镜本 Mock (当前阶段)
- [ ] **分镜生成逻辑**：点击“生成分镜”后，能根据剧本中的场景和动作，Mock 生成 3-5 个分镜条目。
- [ ] **分镜列表视图**：展示镜头号、景别、运动、画面描述、提示词草稿。
- [ ] **分镜编辑**：允许导演手动修改某个镜头的画面描述、图片提示词、视频提示词。
- [ ] **布局适配**：分镜本视图可替换中间编辑器区域或在右侧面板展开。

### W6：分镜一键创建画布节点/导入批量生产板 (当前阶段)
- [ ] **创建节点**：在分镜条目上点击“创建节点”，能向主画布精准下发一个 `gen-image` 或 `gen-video` 节点。
- [ ] **参数传递**：新建的节点中，自动填入该分镜的提示词（Prompt）、角色参考、环境参考，并在 Node Settings 中绑定 `source: writing-studio` 及 `shotId`。
- [ ] **导入批量生产板**：点击“导入批量生产板”，能将当前场次的所有分镜一次性导入生产板的表格中，每行对应一个镜头。

### W7：任务分发给组员 (当前阶段 Mock，后期接真实后端)
- [ ] **任务创建**：导演在分镜本点击“分发任务”，可选择项目组成员（当前以 Mock 列表展示）。
- [ ] **任务列表（组员视角）**：组员能在“我的任务”中看到被分配的分镜制作任务，包含镜号、要求、提示词。
- [ ] **状态流转**：支持任务状态从“待接收” -> “进行中” -> “已提交”的 Mock 流转。

## 2. 剧集制素材库真实后端表草案

以下表结构基于关系型数据库（如 MySQL/PostgreSQL）设计，包含核心的关联外键和审计字段。

### 2.1 剧项目与剧集表
**`writing_projects` (剧项目)**
- `id` (PK, UUID)
- `team_id` (FK，关联大组/小组)
- `title` (VARCHAR，剧名)
- `genre` (VARCHAR，类型)
- `cover_url` (VARCHAR，封面图 OSS 路径)
- `synopsis` (TEXT，简介)
- `status` (ENUM: 'active', 'archived')
- `created_by` (FK，创建人)
- `created_at`, `updated_at`

**`episodes` (剧集)**
- `id` (PK, UUID)
- `project_id` (FK)
- `episode_number` (INT，集号)
- `title` (VARCHAR，集名)
- `synopsis` (TEXT)
- `status` (ENUM: 'not_started', 'in_progress', 'completed')
- `assignee_id` (FK，本集负责人)
- `created_at`, `updated_at`

### 2.2 设定与资产表 (全剧/分集)
**`story_elements` (角色/场景/道具统一定义)**
- `id` (PK, UUID)
- `project_id` (FK)
- `episode_id` (FK, Nullable。若为空则是全剧资产，有值则是分集新增资产)
- `element_type` (ENUM: 'character', 'location', 'prop')
- `name` (VARCHAR)
- `description` (TEXT，设定描述)
- `visual_prompt` (TEXT，视觉提示词基准)
- `created_at`, `updated_at`

**`text_assets` (文本资产)**
- `id` (PK, UUID)
- `project_id` (FK)
- `episode_id` (FK)
- `asset_type` (ENUM: 'script', 'worldview', 'inspiration', 'storyboard_text')
- `title` (VARCHAR)
- `content` (LONGTEXT，具体文本或 Markdown)
- `last_editor_id` (FK，最后修改人)
- `created_at`, `updated_at`

### 2.3 分镜与产物表
**`storyboard_shots` (分镜表)**
- `id` (PK, UUID)
- `episode_id` (FK)
- `scene_number` (VARCHAR，所属场次)
- `shot_number` (INT，镜号)
- `description` (TEXT，画面描述)
- `camera_angle` (VARCHAR，景别)
- `camera_movement` (VARCHAR，运镜)
- `prompt_draft` (TEXT，提示词)
- `status` (ENUM: 'draft', 'assigned', 'in_progress', 'reviewing', 'approved', 'rejected')
- `assignee_id` (FK，制作人/组员)
- `reviewer_id` (FK，审核人/导演)
- `reviewed_at` (DATETIME)
- `created_at`, `updated_at`

**`shot_media_candidates` (分镜多媒体候选，图片/视频)**
- `id` (PK, UUID)
- `shot_id` (FK)
- `media_type` (ENUM: 'image', 'video', 'audio')
- `oss_key` (VARCHAR，原文件路径)
- `thumb_oss_key` (VARCHAR，缩略图路径)
- `creator_id` (FK，生成者)
- `is_selected` (BOOLEAN，导演是否选定为最终版本)
- `feedback` (TEXT，被驳回时的修改意见)
- `created_at`, `updated_at`

## 3. API 草案 (RESTful)

统一前缀: `/api/v1/writing`

### 3.1 剧项目与剧集 (Projects & Episodes)
- **POST** `/projects`：创建新剧项目。
- **GET** `/projects`：获取当前团队下的剧项目列表（支持分页、筛选）。
- **GET** `/projects/:projectId`：获取单部剧详情及全剧资产概览。
- **PATCH** `/projects/:projectId`：更新剧信息（封面、状态等）。
- **POST** `/projects/:projectId/episodes`：创建新集。
- **GET** `/projects/:projectId/episodes`：获取某剧的所有集列表及状态统计。
- **PATCH** `/episodes/:episodeId`：更新集信息及状态。

### 3.2 剧本文本与解析 (Script & Parsing)
- **GET** `/episodes/:episodeId/text-assets`：获取某集的文本资产列表（剧本、世界观等）。
- **PUT** `/text-assets/:assetId`：全量或增量更新剧本/文本内容（含保存版本逻辑）。
- **POST** `/parse/script`：(无状态工具 API) 提交一段剧本文本，后端调用大模型或正则返回解析好的 `ScriptBlock` 和提取的角色/场景。

### 3.3 分镜本 (Storyboards)
- **POST** `/episodes/:episodeId/storyboard/generate`：根据指定的剧本场景 ID，AI 批量生成分镜草稿。
- **GET** `/episodes/:episodeId/shots`：获取某集的分镜列表。
- **POST** `/episodes/:episodeId/shots`：手动添加分镜。
- **PATCH** `/shots/:shotId`：更新单个分镜的内容（描述、提示词等）。

### 3.4 任务分发与结果回流 (Assignments & Media)
- **POST** `/assignments`：分发任务（Payload 包含 `shot_id`, `text_asset_id`, `episode_id`, `assignee_id`, `title`, `description`, `deadline`）。
- **GET** `/assignments/me`：获取自己接收的任务。
- **GET** `/assignments/sent`：获取自己发出的任务。
- **PATCH** `/assignments/:assignmentId/accept`：组员接收任务，状态变更为 `accepted`。
- **PATCH** `/assignments/:assignmentId/submit`：组员提交任务结果，状态变更为 `submitted`。
- *(注：导入画布、导入批量生产板为前端纯本地状态转换，不直接调用后端 API，生成完成后才涉及回流)*
- **POST** `/shots/:shotId/media-candidates`：组员上传生成的图片/视频到 OSS 后，调用此接口将媒体文件绑定为该分镜的候选资产 (`ShotMediaCandidate`)，并触发提审。

### 3.5 导演审核 (Review)
- **POST** `/shots/:shotId/review`：导演审核。
  - Payload: `{ action: 'approve' | 'reject', selectedMediaId?: string, feedback?: string }`
  - 如果 `approve`，标记 `is_selected = true`，分镜状态置为 `approved`。
  - 如果 `reject`，分镜状态置为 `rejected` 或 `needs_changes`，并将意见反馈给组员。

## 4. 详细测试清单

测试分为单元测试、集成测试、UI/E2E 测试。

### 4.1 写作工作台与解析 (单元/集成测试)
- [ ] **解析准确性**：输入包含 10 个场景、20 句对白的标准剧本，断言解析输出的 JSON 数组结构 100% 正确。
- [ ] **容错解析**：输入缺少空格、大小写混用的剧本，检查解析器是否抛出异常或进行合理降级。
- [ ] **高亮性能**：向编辑器粘贴 5 万字的剧本，验证输入延迟是否超过 100ms（需触发防抖）。
- [ ] **版本对比**：修改 5 行文本，断言 Diff 算法能准确识别出 additions 和 deletions 的行号。

### 4.2 剧集库与单集详情 (UI 测试)
- [ ] **路由与渲染**：点击“素材库” -> 进入剧项目列表 -> 点击《星河归途》 -> 渲染 12 个集的网格 -> 点击第 1 集 -> 渲染左侧文本右侧媒体的单集详情。
- [ ] **折叠面板**：在单集详情中，点击“剧本”、“世界观”的手风琴组件，验证展开和收起动画流畅，文本不溢出。
- [ ] **数据关联**：检查第 1 集详情页右侧的图片，是否与其左侧选中的“分镜 1”完全对应。

### 4.3 画布与生产板联动 (E2E 测试)
- [ ] **一键创建节点**：在分镜列表点击某分镜的“创建图像节点”，切换到画布，断言画布中多出一个 `gen-image` 节点，且其 Prompt 输入框中已填充分镜的 Prompt 草稿。
- [ ] **导入批量板**：框选 5 个分镜，点击导入批量生产板，切换到批量板，断言表格中新增了 5 行数据，且角色、场景、镜号字段映射准确。

### 4.4 团队权限与任务审核 (集成流测试)
- [ ] **权限拦截**：使用“Viewer(只读)”角色的账号尝试调用 `/assignments` 接口，断言返回 `403 Forbidden`。
- [ ] **任务流转闭环**：
  1. 导演 A 创建任务指派给 组员 B。
  2. 组员 B 登录，在“我的任务”中看到任务，点击接收。
  3. 组员 B 提交一张图片。
  4. 导演 A 登录，在审核中心看到该图片。
  5. 导演 A 点击驳回，填写意见。
  6. 组员 B 收到驳回意见。
  7. 组员 B 重新提交图片。
  8. 导演 A 点击通过。
  9. 断言该分镜状态变更为 `approved`，对应集进度条推进。
- [ ] **全集完成计算**：当一集中最后一个分镜被 `approve` 时，验证该集的状态自动变更为 `completed`。

## 5. Codex 审查补充

Gemini 这版可以作为方向稿，但不能直接当数据库和 API 最终契约使用。原因是它有几处和当前项目已有后端不完全对齐。

### 5.1 可以保留的部分

- W1-W7 的功能拆分方向是对的。
- 剧项目、剧集、文本资产、分镜、候选媒体这条主线是对的。
- “导入画布 / 导入批量生产板属于前端本地状态转换，生成结果回流后端”这个判断是对的。
- 测试清单覆盖了写作、剧集库、画布联动、任务审核四条关键链路。

### 5.2 必须修正的点

1. 主键类型不能直接写 `UUID`。
   当前后端已有表统一使用 `BIGINT UNSIGNED AUTO_INCREMENT`，例如 `users`、`teams`、`assets`、`transfers`。新表第一版也应保持 `BIGINT UNSIGNED`，除非后续整体迁移到 UUID。

2. `team_id` 不是“关联大组/小组”的泛称。
   当前已有 `organizations` 表表示大组，`teams` 表表示小组/团队。写作项目建议同时保存 `org_id` 和 `team_id`：
   - `org_id`：所属大组，可为空。
   - `team_id`：实际制作小组，必须有。

3. 媒体候选不要重新存一套 OSS 元数据。
   已有 `assets` 表负责 OSS 文件、缩略图、类型、大小、上传者。`shot_media_candidates` 应该引用 `asset_id`，而不是重新写 `oss_key/thumb_oss_key/creator_id` 一套，避免重复和失真。

4. 缺少剧本版本表。
   W4 需要版本保存和分屏对比，不能只在 `text_assets` 上覆盖写入。需要新增 `text_asset_versions`，保存每次快照、作者、版本名、diff 基准。

5. 缺少评论/批注表。
   后续导演实时批注、编剧改稿、组员沟通都需要结构化存储。建议新增 `writing_comments`，支持挂在 project、episode、text_asset、shot、media_candidate 上。

6. 缺少任务表。
   API 里写了 `/assignments`，但数据库草案没有 `writing_assignments`。任务分发不能只依赖 `storyboard_shots.assignee_id`，因为一个分镜可能多次返工、多次分发、多人协作。

7. 缺少权限矩阵。
   需要明确 owner/admin/member/viewer 在写作项目、剧集、文本、分镜、审核、任务分发里的权限。不能只写 Viewer 403。

8. 阶段划分偏激进。
   Gemini 把 W1-W6 都标成“当前阶段”，这会让执行面太宽。当前建议：
   - 当前阶段：W1、W2、W3。
   - 下一阶段：W4、W5。
   - 再下一阶段：W6、W7。
   - 后期云端：真实任务分发、结果回流、导演审核持久化。

### 5.3 修正后的表草案方向

第一版建议新增这些表：

```sql
writing_projects
writing_episodes
writing_text_assets
writing_text_asset_versions
writing_story_elements
writing_storyboard_shots
writing_shot_media_candidates
writing_assignments
writing_comments
```

关键约束：

- 所有主键使用 `BIGINT UNSIGNED AUTO_INCREMENT`。
- 所有用户引用使用 `BIGINT UNSIGNED` 并关联 `users(id)`。
- 所有团队引用使用 `teams(id)`。
- 所有大组引用使用 `organizations(id)`。
- 分镜媒体候选通过 `asset_id` 关联已有 `assets(id)`。
- 软删除统一使用 `status ENUM(...)`，不要物理删除历史创作数据。
- 审计可复用现有 `audit_logs`。
- 通知可复用现有 `notifications`。

### 5.4 修正后的 API 原则

基础路径建议继续挂在现有 `/api/v1` 下，写作模块使用 `/writing/...` 子路径：

- `GET /writing/projects`
- `POST /writing/projects`
- `GET /writing/projects/:projectId`
- `PATCH /writing/projects/:projectId`
- `GET /writing/projects/:projectId/episodes`
- `POST /writing/projects/:projectId/episodes`
- `GET /writing/episodes/:episodeId/text-assets`
- `PUT /writing/text-assets/:assetId`
- `POST /writing/text-assets/:assetId/versions`
- `GET /writing/text-assets/:assetId/versions`
- `POST /writing/parse/script`
- `GET /writing/episodes/:episodeId/shots`
- `POST /writing/episodes/:episodeId/shots`
- `PATCH /writing/shots/:shotId`
- `POST /writing/shots/:shotId/media-candidates`
- `POST /writing/shots/:shotId/review`
- `POST /writing/assignments`

- `PATCH /writing/assignments/:assignmentId/accept`
- `PATCH /writing/assignments/:assignmentId/submit`
- `POST /writing/comments`

画布和批量生产板仍然先走前端本地转换，不要为了“创建节点”强行加后端 API。

### 5.5 修正后的近期执行顺序

当前不要一次做 W1-W7。建议按下面执行：

1. W1 写作工作台壳子。
   - 新建写作入口。
   - 懒加载写作模块。
   - 三栏 IDE 布局。
   - Mock 项目 / 集 / 场树。

2. W2 剧本解析器。
   - 先做纯前端解析函数。
   - 支持中文场景、角色、对白、动作。
   - 加单元测试。

3. W3 编辑器高亮和右侧大纲。
   - 先用 textarea + overlay 或轻量自绘，不急着接重型编辑器。
   - 大纲、人物统计、点击跳转。

4. 审查 W1-W3。
   - 确认不卡顿。
   - 确认结构能接 W4 版本和 W5 分镜。

5. 再做 W4/W5。
   - 版本保存。
   - 分屏对比。
   - 导演分镜本 Mock。

6. 最后做 W6/W7。
   - 分镜创建画布节点。
   - 分镜导入批量生产板。
   - Mock 任务分发。

## 6. 剩余未完成项梳理

为清晰界定下一阶段的交付目标，现将剩余未完成项分为以下三类：

### 6.1 本地 Mock 仍缺

此类任务不依赖后端 API，需在前端纯本地状态下补充完整：
- **W7 任务分发展示（本地 Mock 流转）**：目前虽然在分镜上有“分发给组员”按钮，但缺少本地的任务中心弹窗/页面来展示“任务池”，以及组员视角的“接收 -> 进行中 -> 提交”状态流转 Mock。
- **导演审核闭环（本地 Mock）**：目前单集详情右侧有通过按钮，但对“打回（Rejected）”和“批注反馈”在本地的状态变更与展示尚不完整。
- **版本比对的复杂交互**：目前基于简单 Diff，若要实现类似 Monaco/CodeMirror 的高亮及“采纳某行修改”，还需在本地完善逻辑。

### 6.2 云端 API / 数据库仍缺

此类任务为本阶段 DeepSeek-4-Pro 的重点，需完成后端基建以便后续前端能用 Cloud Client 替换本地 Mock：
- **写作专有数据库表**：包括 `writing_projects`、`writing_episodes`、`writing_text_assets`、`writing_storyboard_shots`、`writing_assignments`、`writing_comments` 等基建表。

- **资源与媒体的关联关系**：`shot_media_candidates` 和现有全局 `assets` 表的数据打通与 OSS 上传凭证获取接口。

### 6.3 真实多人协作 / 审核仍缺
