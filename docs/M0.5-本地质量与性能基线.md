# M0.5 本地质量与性能基线

更新时间：2026-05-02

## 已落地

- 增加 `npm run check:secrets`：扫描 `src/`、`scripts/`、`docs/` 中常见明文密钥形态。
- 增加 `npm run check:quality`：串联 `check:secrets`、`lint`、`test`、`build`，作为当前可执行质量门禁。
- 调整 Vitest：当前没有测试文件时不再让 `npm run test` 失败，避免空测试阶段阻塞门禁。
- 修复画布拖入视频时的 blob URL 生命周期：删除对应节点或窗口卸载时释放 `URL.createObjectURL` 创建的地址，降低长时间使用的内存堆积风险。
- 修复 Veo 图片预处理临时 blob URL 生命周期：图片压缩完成、失败或跳过压缩时都会释放临时地址。
- 增加画布 FPS 手动采样入口：开发者控制台可执行 `await window.__tapnowPerf.sampleCanvasFps(5000)`，用于 100 节点拖拽抽检。

## 当前基线

- `npm run check:secrets`：通过，未发现常见明文密钥。
- `npm run lint`：通过，但仍有 20 个 warning，集中在主进程旧文件的未使用变量和格式提示。
- `npm run test`：通过；当前覆盖 DAG 引擎与轮询器相关测试。
- `npm run build`：通过；仍有大 chunk 和部分动态导入提示。
- `npm run typecheck`：未纳入 `check:quality`，当前全仓存在大量历史 TS 类型问题，需要单独开一轮类型治理。

## 后续建议

- M0.5-1：使用 `window.__tapnowPerf.sampleCanvasFps(5000)` 完成 100 节点拖拽抽检，记录平均 FPS 与最低帧间隔。
- M0.5-2：继续清理 Base64 大文件持久化路径，优先把视频/大图统一转缓存文件引用，并补一轮 30 分钟内存快照。
- M0.5-4：等核心 TS 问题分批收敛后，再把 `npm run typecheck` 加回严格质量门禁。
