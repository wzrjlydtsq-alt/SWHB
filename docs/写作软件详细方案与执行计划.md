# 星河写作工作台详细方案与执行计划

更新时间：2026-05-06  
定位：编剧写作、导演拆解、分镜生成、任务分发、组员生产、素材回流的一体化创作工作台。

---

## 1. 产品定位

星河写作工作台不是单纯的“富文本编辑器”，而是一个从剧本文字一路流转到 AI 生成生产的协作系统。

核心目标：

- 编剧能像写代码一样管理剧本：项目树、集数、场次、版本、搜索、分屏对比、自动高亮。
- 导演能把剧本拆成分镜本：镜号、画面、景别、运动、人物、场景、道具、提示词。
- 制作组能接收导演分发的任务：一键创建画布节点，或导入批量生产板。
- 生成结果能回流：回到对应剧集、分镜、人物、场景、道具、云素材库。
- 团队能协作：批注、审核、分发、返工、版本留痕。

一句话：

> 编剧写剧本，导演拆镜头，组员做资产，系统负责把“文字”变成“可生产任务”。

### 1.1 形态决策

写作工作台第一阶段不是单独新软件，也不是画布里的一个节点。

明确采用：

> 现有星河智慧软件里的“懒加载独立一级工作台”。

它和现有模块的关系：

- 与画布、批量生产板、云素材库、AI 对话并列，是一个一级入口。
- 平时不打开写作工作台时，它不加载、不渲染、不解析剧本、不订阅主画布状态。
- 打开写作工作台后，才加载写作模块代码和写作数据。
- 写作工作台只在“一键创建节点”“导入批量生产板”“保存到云素材库”这些动作发生时和其他模块交换数据。
- 不允许把剧本编辑器塞进画布节点里。
- 不允许把写作模块常驻挂在主界面后台。

为什么不先做独立软件：

- 当前账号、云素材、画布、批量生产板、团队权限都已经在星河智慧里，复用成本最低。
- 独立软件会立刻带来登录、项目同步、素材共享、任务分发的重复建设。
- 写作模块成熟后，可以再拆成独立 Web 版或独立窗口。

为什么不做成画布节点：

- 剧本是长文本，画布节点适合生成流程，不适合长文编辑、版本对比、批注。
- 画布节点如果承载剧本编辑器，会导致缩放、拖拽、渲染、保存都变复杂。
- 写作工作台是上游生产系统，画布是下游生成系统，两者要打通但不要绑死。

## 2. 用户角色

### 2.1 编剧

主要工作：

- 创建项目、季、集、场。
- 编写剧本正文。
- 管理角色、地点、道具、时间线。
- 对比版本。
- 接收导演或制片的批注。
- 锁定某一版剧本并提交导演。

需要的能力：

- 类 IDE 编辑器。
- 自动识别剧本格式。
- 场次导航。
- 角色出现统计。
- 分屏对比。
- 批注处理。
- 版本保存。

### 2.2 导演

主要工作：

- 阅读导演剧本。
- 对每集拆分镜。
- 抽取全局人物、场景、道具、风格。
- 为每个镜头生成提示词草稿。
- 把任务分发给组员。
- 审核组员回传结果。

需要的能力：

- 导演剧本阅读视图。
- 分镜本编辑器。
- 全局资产提示词库。
- 一键创建画布节点。
- 一键导入批量生产板。
- 分发任务。
- 批注和返工。

### 2.3 组员

主要工作：

- 接收任务。
- 查看任务所需人物、场景、道具、参考图、提示词。
- 一键创建节点或导入批量生产板。
- 生成内容。
- 提交结果。

需要的能力：

- 我的任务。
- 接收/拒绝任务。
- 一键创建节点。
- 导入批量生产板。
- 上传结果。
- 与导演沟通返工。

### 2.4 管理员 / 制片

主要工作：

- 管理项目成员。
- 管理大组、小组、权限。
- 查看项目进度。
- 管理剧集状态。
- 管理交付物。

需要的能力：

- 权限管理。
- 项目看板。
- 任务进度统计。
- 审核记录。
- 导出归档。

## 3. 总体工作流

### 3.1 从剧本到生产的完整链路

1. 创建项目。
2. 创建季和集。
3. 编剧在 IDE 风格编辑器中写剧本。
4. 系统自动解析剧本结构：场次、角色、对白、动作、地点、时间。
5. 编剧保存版本。
6. 编剧提交“导演剧本”。
7. 导演打开导演剧本。
8. 导演生成或手动编辑分镜本。
9. 导演抽取全局人物、场景、道具、风格提示词。
10. 导演把分镜任务、人物任务、场景任务、道具任务分发给组员。
11. 组员接收任务。
12. 组员选择“一键创建画布节点”或“导入批量生产板”。
13. 组员生成图片/视频/音频等内容。
14. 组员提交结果。
15. 导演审核通过或退回修改。
16. 通过的结果进入云素材库、剧集交付物和项目仓库。

### 3.2 MVP 流程

第一版不要一口吃掉实时协作和复杂审批，先跑通：

1. 编剧写剧本。
2. 系统解析场次、角色、对白。
3. 导演生成分镜 mock。
4. 分镜可一键创建节点。
5. 分镜可导入批量生产板。
6. 分镜可分发给组员。
7. 组员接收后能创建节点或导入批量生产板。

## 5. 界面设计方案

### 5.1 整体布局

写作工作台建议参考 IDE：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：项目名 / 当前集 / 保存状态 / 提交导演 / 分屏 / AI 拆解 │
├──────────────┬───────────────────────────────┬───────────────┤
│ 左侧项目树   │ 中间剧本编辑器                │ 右侧信息面板  │
│              │                               │               │
│ 项目         │ 场景标题高亮                  │ 大纲          │
│ 第 1 季      │ 角色名高亮                    │ 人物          │
│ 第 1 集      │ 对白高亮                      │ 场景          │
│ 场 1         │ 动作描述高亮                  │ 批注          │
│ 场 2         │                               │ 版本          │
└──────────────┴───────────────────────────────┴───────────────┘
```

入口建议：

- 底部工具栏新增“写作”入口，或侧边栏新增一级入口。
- 点击入口后打开完整工作台视图。
- 工作台可以是全屏面板、独立路由式页面，或可关闭的大面板。
- 不建议做成普通弹窗，因为剧本编辑需要长时间沉浸使用。

加载约束：

- `WritingStudio` 必须使用动态导入或懒加载。
- 写作工作台未打开时，不得加载大型编辑器依赖。
- 写作工作台未打开时，不得读取大文本、不运行 parser、不计算 diff。
- 写作模块状态优先放在模块内部或专用 store，不能把大段剧本文本塞进全局主 store。

### 5.2 左侧项目树

层级：

- 项目
- 季
- 集
- 场
- 文档
- 人物设定
- 场景设定
- 道具设定
- 分镜本
- 任务

交互：

- 点击集：打开该集剧本。
- 点击场：跳转编辑器对应位置。
- 右键集：新建场、重命名、复制、导出。
- 右键场：拆分、合并、标记完成。

### 5.3 中间编辑器

第一版可以先用自研 textarea + overlay 高亮，后续再换 Monaco / CodeMirror。

原因：

- MVP 更快。
- 现在重点是工作流，不是编辑器内核。
- 后续如果要 IDE 体验，CodeMirror 6 比较适合自定义语法高亮和批注。

文本块样式：

- 场景标题：青色、加粗。
- 角色名：金色、居中或左缩进突出。
- 对白：浅色正文。
- 动作描述：普通正文。
- 括号提示：灰色斜体。
- 转场：紫色或蓝色。
- AI 标记内容：绿色虚线下划线。
- 批注内容：黄色背景。

## 6. 剧本格式解析规则

### 6.1 支持格式

中文常见剧本：

```text
场景一  夜  室内  林晓家客厅

林晓坐在窗边，手里攥着一张旧照片。

林晓
你真的回来了吗？

（门外传来钥匙声）

切至：
```

影视工业格式：

```text
INT. APARTMENT - NIGHT

Lin sits beside the window.

LIN
Are you really back?

CUT TO:
```

网文/小说式：

```text
第一场：雨夜的车站

雨水砸在站台上。林晓抬头，看见远处的人影。
```

### 6.2 ScriptBlock 类型

```ts
type ScriptBlock =
  | SceneHeadingBlock
  | ActionBlock
  | CharacterBlock
  | DialogueBlock
  | ParentheticalBlock
  | TransitionBlock
  | NoteBlock

type SceneHeadingBlock = {
  id: string
  type: 'scene-heading'
  text: string
  sceneNumber?: string
  location?: string
  timeOfDay?: string
  interiorExterior?: 'INT' | 'EXT' | 'UNKNOWN'
}

type ActionBlock = {
  id: string
  type: 'action'
  text: string
}

type CharacterBlock = {
  id: string
  type: 'character'
  text: string
  characterName: string
}

type DialogueBlock = {
  id: string
  type: 'dialogue'
  speaker: string
  text: string
}

type ParentheticalBlock = {
  id: string
  type: 'parenthetical'
  text: string
}

type TransitionBlock = {
  id: string
  type: 'transition'
  text: string
}

type NoteBlock = {
  id: string
  type: 'note'
  text: string
}
```

### 6.3 解析优先级

1. 明确场景标题优先。
2. 明确转场词优先。
3. 括号行识别为 parenthetical。
4. 短行 + 上下文判断为角色名。
5. 角色名后一段识别为对白。
6. 其他识别为动作描述。

### 6.4 场景标题识别规则

识别：

- `场景一`
- `场景1`
- `第一场`
- `第 1 场`
- `1.`
- `INT.`
- `EXT.`
- `内景`
- `外景`

时间关键词：

- 日
- 夜
- 清晨
- 黄昏
- 傍晚
- 雨夜
- 雪夜

空间关键词：

- 室内
- 室外
- 内景
- 外景
- 家
- 客厅
- 街道
- 学校
- 医院

### 6.5 角色名识别规则

第一版用启发式：

- 单独一行。
- 字数 2-12。
- 不是标点开头。
- 不是场景标题。
- 不是转场。
- 下一行不是空白时，高概率是角色名。

后续增强：

- 从人物库匹配。
- 从全局角色表匹配。
- AI 辅助识别。

## 8. AI 能力设计

### 8.1 编剧侧 AI

功能：

- 根据一句话生成剧集大纲。
- 根据大纲扩写场景。
- 调整对白风格。
- 检查角色口吻一致性。
- 检查剧情漏洞。
- 提取人物、场景、道具。
- 生成剧情摘要。

第一版先做：

- 提取人物。
- 提取场景。
- 提取道具。
- 提取场次摘要。

### 8.2 导演侧 AI

功能：

- 从剧本生成分镜草稿。
- 从场景生成镜头列表。
- 给镜头生成图片提示词。
- 给镜头生成视频提示词。
- 生成统一风格提示词。
- 生成角色视觉提示词。
- 生成场景视觉提示词。

第一版先做：

- 从一场戏生成 3-8 条分镜草稿。
- 每条分镜包含：镜号、画面描述、景别、运动、角色、场景、提示词。

### 8.3 组员侧 AI

功能：

- 接收任务后自动创建节点。
- 根据任务生成节点提示词。
- 根据任务导入批量生产板。
- 根据退回意见修改提示词。

第一版先做：

- 一键创建 `gen-image` / `gen-video` 节点。
- 一键导入批量生产板。

## 9. 与现有系统的连接

### 9.1 连接画布节点

从分镜创建节点：

- 图片分镜：创建 `gen-image` 节点。
- 视频分镜：创建 `gen-video` 节点。
- 剧本文档：创建 `novel-input` 节点。
- 分镜说明：可创建 `director-node` 或 `sticky-note`。

节点 settings 建议：

```ts
type WritingNodeSettings = {
  source: 'writing-studio'
  sourceType: 'storyboard-shot' | 'script-document' | 'scene-summary'
  projectId: string
  projectTitle?: string
  episodeId: string
  episodeTitle?: string
  sceneId?: string
  sceneTitle?: string
  shotId?: string
  shotNumber?: number
  shotTitle?: string
  prompt?: string
  videoPrompt?: string
  negativePrompt?: string
  manualImages?: string[]
  characters?: string[]
  props?: string[]
  cameraAngle?: string
  cameraMovement?: string
  refCharacters?: Array<{ id?: string; name: string; prompt?: string; path?: string }>
  refScenes?: Array<{ id?: string; name: string; prompt?: string; path?: string }>
  refProps?: Array<{ id?: string; name: string; prompt?: string; path?: string }>
}
```

W6/W7 桥接硬性规则：

- 所有从写作工作台流出的数据都必须带 `source: 'writing-studio'`。
- 分镜级数据统一用 `sourceType: 'storyboard-shot'`，不要再新造 `storyboardId`、`sceneShot`、`fromWriting` 等同义字段。
- `shotId` 是内部稳定 ID，`shotNumber` 是给用户看的镜号；两者都要保留。
- 画布节点和批量生产行的 `projectId / episodeId / sceneId / shotId` 字段名必须一致，方便后续生成结果回流到剧集制素材库。
- 当前 Mock 数据没有真实 `projectId / episodeId / sceneId` 时，先用现有 mock id 或空字符串占位，但字段结构不能缺。
- 图片节点使用 `prompt = shot.imagePrompt`；视频节点使用 `videoPrompt = shot.videoPrompt`，不要把视频提示词塞进 `prompt` 后丢失语义。

### 9.2 连接批量生产板

从分镜导入批量生产板：

- 每个镜头生成一行。
- 镜号进入 `name`。
- 镜头提示词进入 `prompt`。
- 人物进入 `refCharacters`。
- 道具进入 `refProps`。
- 场景进入 `refScenes`。
- 参考图进入 `refImages`。
- 参考音频进入 `refAudios`。
- 参考视频进入 `refVideos`。
- 秒数进入 `duration`。

批量生产行 metadata 建议：

```ts
type WritingProductionRowMeta = {
  source: 'writing-studio'
  sourceType: 'storyboard-shot'
  projectId: string
  projectTitle?: string
  episodeId: string
  episodeTitle?: string
  sceneId?: string
  sceneTitle?: string
  shotId: string
  shotNumber: number
  cameraAngle?: string
  cameraMovement?: string
  characters?: string[]
  props?: string[]
}
```

批量生产行落地规则：

- `name` 统一为 `镜头 ${shotNumber}`，如果有场景名可追加 ` - ${sceneTitle}`。
- 视频行 `prompt` 使用 `shot.videoPrompt`；图片行 `prompt` 使用 `shot.imagePrompt`。
- `refCharacters/refProps/refScenes` 在没有素材路径时也可以先写 `{ name }`，不要硬造不存在的本地路径。
- 导入后自动打开批量生产板，用户必须能看到新增行。
- 不要求本阶段打通真实生成结果回流，先保证 metadata 进入行数据。

### 9.3 连接云素材库

生成结果回流：

- 节点生成完成后可保存到云素材库。
- 保存时绑定 `projectId / episodeId / sceneId / shotId`。
- 云素材可反查来自哪个分镜任务。
- 导演审核通过后标记为该镜头最终素材。

### 9.4 连接团队任务

分发任务用现有云团队能力扩展：

- 任务可以基于大组/小组。
- 导演向小组成员发送任务。
- 组员接收后进入“我的任务”。
- 任务结果提交后通知导演。

### 9.5 剧集制素材库改版

写作工作台上线后，“素材库”不应该继续只是按图片、视频、音频平铺。它应该升级为“剧集制项目素材仓库”。

核心原则：

- 素材库就是素材库，不再混入团队管理。
- 团队管理、成员、邀请码、审核、角色权限，统一收进用户头像/团队头像入口。
- 素材库主视图展示一部部剧。
- 点进某部剧后，再按全剧资产、分集资产、分镜资产组织内容。
- 图片、视频、文本都必须能追溯到剧、集、分镜、制作人、最后修改日期、审核状态。

#### 9.5.1 顶层：剧集项目列表

素材库打开后第一层显示“剧项目卡片”。

每个剧项目卡片包含：

- 剧名。
- 封面。
- 类型/标签。
- 集数。
- 完成进度。
- 最近修改日期。
- 负责人。
- 状态：筹备中、制作中、已完成、归档。

视觉：

- 卡片横向或网格排列。
- 封面在上方或左侧。
- 进度用小绿标/灰标显示。
- 完成剧集数，例如 `8 / 12 集完成`。

点击剧项目后进入该剧的剧集仓库。

#### 9.5.2 剧项目内：全剧资产 + 分集资产

剧项目内顶部始终显示“全剧资产”入口：

- 全剧角色。
- 全剧场景。
- 全剧道具。
- 全剧世界观。
- 全剧风格参考。
- 全剧灵感板。

当用户切换到某一集时，额外显示该集资产：

- 本集新增角色。
- 本集新增场景。
- 本集新增道具。
- 本集参考图。
- 本集参考视频。
- 本集参考音频。
- 本集分镜本。

规则：

- 全剧角色/场景/道具是跨集复用资产。
- 分集角色/场景/道具是该集独有或该集变体。
- 分集资产可以提升为全剧资产。
- 全剧资产可以被某一集引用，但不复制多份。

#### 9.5.3 文本资产分类

一部剧里的文本资产包含：

- 剧本。
- 世界观。
- 灵感。
- 分镜本。
- 角色设定。
- 场景设定。
- 道具设定。
- 导演批注。
- 制作说明。

文本资产不是普通“document”一股脑放一起，而要按语义分类。

建议类型：

```ts
type WritingTextAssetType =
  | 'script'
  | 'world_bible'
  | 'inspiration'
  | 'storyboard'
  | 'character_profile'
  | 'scene_profile'
  | 'prop_profile'
  | 'director_note'
  | 'production_note'
```

#### 9.5.4 分集预览窗格

点进某部剧后，默认显示每一集的长方形预览窗格。

每个窗格包含：

- 集号。
- 集名。
- 封面或代表帧。
- 剧本状态。
- 分镜状态。
- 图片状态。
- 视频状态。
- 审核状态。
- 最后修改日期。
- 主要负责人。

状态标记：

- 全部通过：绿标。
- 未完成：灰标。
- 有返工：黄标。
- 审核失败：红标。

完成规则：

- 一集内所有必要分镜都通过导演审核，才算该集完成。
- 只生成了图片但视频未确认，不算完成。
- 有任何分镜处于返工/未审核，该集不算完成。

#### 9.5.5 单集详情

点进某一集后，布局建议：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部：剧名 / 第几集 / 状态 / 负责人 / 最后修改日期 / 进度     │
├──────────────────────┬───────────────────────────────────────┤
│ 左侧：可折叠文本区    │ 右侧：图片组 / 备选视频 / 审核区       │
│                      │                                       │
│ 剧本                 │ 分镜 001 图片组                        │
│ 世界观补充           │ 分镜 001 备选视频                      │
│ 灵感                 │ 导演选择通过/退回                      │
│ 分镜本               │ 制作人、最后修改日期                   │
└──────────────────────┴───────────────────────────────────────┘
```

“压缩起来的文本”定义：

- 左侧文本不是全文展开，而是折叠面板。
- 剧本、世界观、灵感、分镜本各自是一个可展开/折叠的 section。
- 分镜本内部每个分镜也可以折叠。
- 默认只显示标题、摘要、状态、最后修改时间。
- 点击后展开全文或该分镜详细文本。

#### 9.5.6 分镜级资产

每集里每个分镜对应：

- 分镜编号。
- 分镜文本。
- 画面描述。
- 图片组。
- 备选视频。
- 参考音频。
- 制作人。
- 最后修改日期。
- 审核状态。
- 导演确认勾选。
- 返工意见。

图片组：

- 可以有多张候选图。
- 导演可以选一张作为主图。
- 其他图保留为备选。

备选视频：

- 可以有多个候选视频。
- 导演可以选一个通过。
- 未通过视频保留为历史。

状态：

- `not_started`
- `in_progress`
- `submitted`
- `approved`
- `needs_changes`
- `rejected`

分镜通过规则：

- 必须有导演勾选通过。
- 如果该分镜要求视频，则视频也必须通过。
- 如果只要求图片，则主图通过即可。

#### 9.5.7 制作人和修改记录

每个分镜资产必须显示：

- 谁做的。
- 谁最后修改。
- 最后修改日期。
- 谁审核。
- 审核日期。

建议字段：

```ts
type ShotProductionStatus = {
  shotId: string
  assigneeId?: number
  assigneeName?: string
  lastEditorId?: number
  lastEditorName?: string
  lastModifiedAt: string
  reviewerId?: number
  reviewerName?: string
  reviewedAt?: string
  status: 'not_started' | 'in_progress' | 'submitted' | 'approved' | 'needs_changes' | 'rejected'
}
```

#### 9.5.8 团队管理入口拆分

当前云素材面板里混着：

- 大组。
- 小组。
- 邀请码。
- 审核。
- 成员。
- 上传素材。
- 素材列表。

后续要拆开。

素材库只保留：

- 剧项目列表。
- 剧内资产。
- 上传/拖拽/预览/筛选。
- 分镜图片和视频审核。

团队管理移到头像入口：

- 点击用户头像或团队头像打开团队管理浮层。
- 管理大组。
- 管理小组。
- 查看成员。
- 邀请码。
- 审核申请。
- 角色权限。
- 删除/归档团队。

这样素材库不会变成“素材 + 团队设置”的混合面板。

#### 9.5.9 面板形态

云素材库/剧集素材库面板应改为悬浮面板。

要求：

- 可拖动。
- 可调整大小。
- 可最大化。
- 可最小化/收起。
- 记住上次位置和大小。
- 不遮挡小精灵状态。
- 不和 AI 对话面板绑定位置。
- 打开团队管理时使用独立小浮层，不挤占素材库内容区。

默认尺寸：

- 宽度：`min(1180px, 88vw)`。
- 高度：`min(760px, 82vh)`。
- 最小宽度：`760px`。
- 最小高度：`480px`。

## 11. 性能与臃肿控制

写作工作台允许嵌在现有软件里，但必须按“独立模块寄居在现有壳里”的方式实现，不能拖慢画布和现有生成流程。

### 11.1 模块加载

硬性要求：

- 写作工作台必须懒加载。
- 不打开写作入口时，不渲染任何写作组件。
- 不打开写作入口时，不加载 CodeMirror / Monaco / diff 库等重依赖。
- 不打开写作入口时，不订阅剧本数据、不解析文本、不启动自动保存。

推荐实现：

```ts
const WritingStudio = React.lazy(() => import('./features/writing/WritingStudio'))
```

### 11.2 状态隔离

硬性要求：

- 剧本文本不放进主画布节点数据。
- 剧本文本不放进全局 `useAppStore` 的高频订阅区域。
- 写作工作台使用模块内部状态，或单独的 writing store。
- 只把“当前是否打开写作工作台”这种轻量 UI 状态放入全局 store。

原因：

- 剧本文本可能是几十万字。
- 如果进入全局 store，画布、节点、AI 对话等模块可能被无意义触发重渲染。

### 11.3 输入与解析

硬性要求：

- parser 不能每输入一个字就全量同步解析。
- 解析必须防抖，建议 300-500ms。
- 大文本后续要支持增量解析或 Web Worker。

MVP 允许：

- 先用 textarea + parsed preview。
- 先做全量解析，但必须防抖。

后续优化：

- CodeMirror 6 语法高亮。
- 虚拟滚动。
- Web Worker 解析。
- 分块解析。

### 11.4 版本与 diff

硬性要求：

- diff 只在用户打开分屏对比时计算。
- 不在普通编辑状态持续计算 diff。
- 版本快照存储要节流，不能每次键入都写 localStorage 或云端。

建议：

- 本地自动保存间隔 5-10 秒。
- 用户停止输入 2 秒后保存草稿。
- 手动保存版本才生成正式版本。

### 11.5 云同步

硬性要求：

- 不每次输入都请求后端。
- 云同步必须节流或走后台队列。
- 网络失败不阻塞本地写作。

建议：

- 本地先保存。
- 空闲时同步云端。
- 同步状态显示：已保存本地、同步中、已同步、同步失败。

### 11.6 与画布解耦

硬性要求：

- 写作工作台不持续监听画布节点状态。
- 画布不持续监听写作编辑器文本。
- 只在用户点击“一键创建节点”时，把 shot/script 数据交给画布。
- 只在用户点击“导入批量生产板”时，把 shot 列表交给批量生产板。

这能保证：

- 写剧本不卡画布。
- 画布拖拽不卡写作。
- 批量生产板生成不卡编辑器输入。

## 14. 执行排期

### W0：方案冻结

目标：

- 明确写作工作台 MVP 范围。
- 明确先本地 mock，后接云。
- 明确不做实时协作。

完成标志：

- 本文档确认。
- Claude 可以按任务执行。

### W1：写作工作台壳子

耗时：1-2 天

任务：

- 新建 WritingStudio。
- 左侧项目树。
- 中间编辑器。
- 右侧面板。
- 接入侧边栏入口。
- mock 项目/集/场。

完成标志：

- 能打开写作工作台。
- 能切换集和场。
- 能编辑文本。

### W2：剧本解析与高亮

耗时：2-3 天

任务：

- 新建 scriptParser。
- 解析 ScriptBlock。
- 自动识别场景、角色、对白、动作。
- 编辑器按块高亮。
- 右侧大纲随文本更新。

完成标志：

- 输入剧本后能看到场次大纲。
- 角色名和对白能自动改色。
- 解析器有基础测试。

### W3：版本与分屏对比

耗时：2 天

任务：

- 手动保存版本。
- 自动保存草稿。
- 版本列表。
- 分屏对比两个版本。
- 简单 diff 高亮。

完成标志：

- 可以保存版本。
- 可以选择两个版本分屏对比。

### W4：导演分镜本 Mock

耗时：2-3 天

任务：

- 新建 DirectorScriptBoard。
- 从剧本场次生成 mock 分镜。
- 分镜列表和详情编辑。
- 每条分镜有图片提示词、视频提示词。
- 支持一键创建节点 mock。
- 支持导入批量生产板 mock。

完成标志：

- 能从某集打开分镜本。
- 能看到分镜列表。
- 能编辑镜头提示词。

### W5：接入画布和批量生产板

耗时：3-5 天

任务：

- 分镜一键创建 `gen-image` / `gen-video`。
- 分镜导入批量生产板。
- 绑定 source metadata。
- 生成结果可回流到分镜记录。

完成标志：

- 分镜能创建真实画布节点。
- 分镜能生成批量生产行。

### W6：任务分发

耗时：3-5 天

任务：

- 写作任务模型。
- 分发给组员。
- 组员接收。
- 组员一键创建节点或导入批量生产板。
- 提交结果。

完成标志：

## 18. 风险与决策

### 风险 1：编辑器太复杂

处理：

- MVP 不上 Monaco。
- 先做 textarea + parsed preview。
- 验证流程后再换 CodeMirror 6。

### 风险 2：剧本格式不统一

处理：

- 第一版只支持常见中文格式。
- 解析不准时允许用户手动标记。
- 后续引入 AI 修正解析结果。

### 风险 3：任务分发和云素材重叠

处理：

- 素材传递用于“文件/素材”。
- 写作任务用于“生产任务”。
- 两者可以引用同一个 asset，但状态机不同。

### 风险 4：权限体系变复杂

处理：

- 第一版本地 mock 不管权限。
- 接云时复用大组/小组权限。
- 项目角色只做项目内补充，不另起一套完全割裂的系统。

### 风险 5：生成节点字段不统一

处理：

- 新增 `writingToCanvas` 适配层。
- 写作工作台不直接操作所有节点内部细节。
- 后续节点字段变化只改适配层。
