# 星河写作工作台 W1-W3 测试方案

本文档专门针对写作工作台的第一阶段（W1 壳子、W2 剧本解析器、W3 编辑器高亮与大纲）制定详细的测试方案。

## 1. 剧本解析器（W2）中文测试样例 (20 条)

解析器需将纯文本准确映射为 `scene` (场景), `action` (动作), `character` (角色), `dialogue` (对白), `parenthetical` (提示), `transition` (转场) 等 Block 类型。

### [样例 01] 标准中文场景格式
- **原始剧本文本**：
  ```text
  场景一 日 内景 林晓家客厅
  
  阳光透过窗帘缝隙洒进来。林晓坐在沙发上发呆。
  ```
- **期望场景数量**：1
- **期望角色名**：无
- **期望 Block 类型列表**：`[scene, action]`

### [样例 02] 欧美常用翻译格式 (INT/EXT)

- **期望角色名**：无

### [样例 03] 角色与标准对白

## 2. W1-W3 UI 测试清单

### W1: 写作工作台壳子
- [ ] **入口懒加载**：刷新应用后，初始状态下监控 Network 或 Performance 面板，确保不加载写作模块的庞大 JS Bundle。点击入口后，触发按需加载。
- [ ] **布局响应**：测试左、中、右三栏布局的边界调整（Resizer），拖动分隔线时页面不应卡顿，且有最小/最大宽度限制。
- [ ] **全局状态隔离**：打开写作工作台后，再切回画布或团队素材库，验证写作工作台的状态（如打开的文件、光标位置）被正确缓存且未污染全局 Store。

### W3: 编辑器高亮和右侧大纲
- [ ] **实时高亮视觉**：验证 `scene`、`character`、`dialogue` 是否显示为设计的不同颜色/字重。特别检查中英文混排时的渲染对齐。
- [ ] **大纲自动生成**：在编辑器中输入“场景二 日 内景 警局”，观察右侧“大纲”面板是否在防抖时间后立刻新增该场次条目。
- [ ] **角色列表更新**：在编辑器中新增对白“陌生人\n你是谁？”，右侧“角色”面板应自动增加“陌生人”这一词条。
- [ ] **双向跳转锚点**：
  - 点击大纲中的“场景二”，编辑器视图应平滑滚动并将光标置于对应行。
  - 在编辑器中滚动浏览到“场景三”，右侧大纲面板应自动高亮显示“场景三”所在的条目项（Scroll Spy）。

## 3. W1-W3 性能测试清单

### 解析器性能 (Debounce & AST)
- [ ] **打字无阻塞**：在编辑器中快速连续输入文本，确保键盘响应延迟（Input Latency）始终在 16ms 以内。解析任务（Parse）必须在 Web Worker 或触发防抖（300-500ms 停顿后）执行。
- [ ] **全量与增量解析**：针对 5 万字（约 90 分钟电影体量）的长剧本：
  - 初次加载解析耗时需低于 500ms。
  - 单行修改时的增量更新（或优化后的全量替换）不引起 UI 明显卡顿（Long task < 50ms）。

### 渲染性能
- [ ] **长列表滚动**：在 5 万字的剧本编辑器中快速滚动，确保 FPS 维持在 60，无明显掉帧。要求编辑器底层使用了虚拟滚动（Virtualization）或 CodeMirror 的视口渲染优化。
- [ ] **大纲渲染**：右侧大纲包含超过 200 个场景时，展开/折叠大纲的操作不应产生超过 100ms 的延迟。

## 4. W1-W3 回归测试清单

此阶段完成后，不能破坏现有系统的稳定性：

- [ ] **云素材库兼容**：确保写作模块引入的新类型（`SeriesTextAsset` 等）不会导致原有的素材库网格视图、图片预览、拖拽逻辑崩溃。
- [ ] **团队管理浮层**：在写作工作台视图下，依然能通过头像唤出团队管理浮层，且信息加载正常。
- [ ] **画布节点拖拽验证**：从写作模块切回画布后，测试原有从素材库向画布拖拽图片的逻辑，确认 `cloudAssetDrop.ts` 中的事件监听未受干扰。
- [ ] **内存泄漏检查**：反复在“画布”和“写作工作台”之间切换 20 次，通过 Chrome DevTools Memory 面板截取 Heap Snapshot，验证 DOM 节点数和 Event Listeners 是否有异常增长。
