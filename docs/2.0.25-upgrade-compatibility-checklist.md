# 2.0.25 升级兼容处理清单

## 目标

减少用户更新后因为旧配置、旧项目数据、旧缓存引用和前端持久化状态导致的异常。用户可以从 2.0.3 等老版本直接升级到当前版本，不需要手动逐级升级。

## 已完成

- [x] 增加应用数据版本号 `tapnow_data_version`。
- [x] 启动时运行主进程迁移队列。
- [x] 迁移前备份 SQLite 数据库、项目 JSON 和 settings 快照。
- [x] 为项目 JSON 增加 `schemaVersion`。
- [x] 为旧项目 JSON 自动补齐 `cacheRoot`、`nodeGroups`、`nodes`、`connections`、`history` 等默认字段。
- [x] 旧全局缓存配置只做兼容快照，不再写回缓存后端。
- [x] 增加 `system:migration-status` 只读诊断入口。
- [x] 取消旧的“版本更新后让用户清缓存”弹窗。

## 待做

- [x] 增加“修复当前项目”入口，只修复项目数据和软件托管缓存，不删除用户源素材。
- [x] 将迁移状态接入诊断面板和客服复制信息。
- [x] 对旧 `LocalCache` 引用做更细的懒迁移策略，项目保存时逐步转为项目缓存上下文。
- [x] 为缓存迁移、旧项目加载、旧历史记录引用补充回归测试。
- [x] 增加迁移失败后的恢复 UI，允许用户打开备份目录或重新执行项目修复。

## 验收

- 老版本项目升级后能正常打开。
- 历史记录、节点素材、资产库缩略图不串项目。
- 清理缓存只作用于当前项目的软件托管缓存。
- 用户清空项目缓存目录后回到默认项目缓存目录。
- 出现迁移失败时能给出明确日志和可恢复入口。
