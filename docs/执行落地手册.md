## 五、M1.5 — DAG 引擎增强（1 周，与 M2 并行）

**目标**：让工作流引擎从"能跑"升级到"好用"。

### 当前执行排期（本轮）

| 状态 | # | 任务 | 完成标志 |
| --- | --- | --- | --- |
| [x] | 1.5-1 | 节点并行执行：按拓扑层级分组，层内 `Promise.allSettled()` 并发调度 | 3 个无依赖节点耗时 ≈ 单个最慢节点（测试验证 108ms vs 300ms 串行） |
| [x] | 1.5-2 | 断点续跑：失败节点标记 + 下游级联 skip + `resumeWorkflow()` 从失败处重跑 | 5 节点流程中第 3 个失败，resume 只重跑失败+skipped 节点，已完成节点不重复执行 |
| [x] | 1.5-3 | ModelProvider 统一适配层：`IModelProvider` 接口 + 火山引擎/Midjourney 两个实现 + 注册表路由 | 两个 Provider 实现同一接口，可通过 modelId 自动路由 |

### 技术实现

- **并行执行**：`graph.ts` 新增 `buildExecutionLayers()` 按拓扑层分组 → `engine.ts` 层内 `Promise.allSettled()` 并发
- **断点续跑**：`engine.ts` 新增 `nodeStatuses` Map 跟踪每节点状态（pending/running/completed/failed/skipped），失败时级联 skip 下游，`resumeWorkflow()` 保留已完成输出只重跑失败链路
- **Provider 适配层**：`src/renderer/services/providers/` 目录含 `IModelProvider.ts` 接口、`VolcanoProvider.ts`（runtime: both）、`MidjourneyProvider.ts`（runtime: local）、`registry.ts` 路由注册表
- 涉及团队凭证、成本统计、云端路由的 Provider 后续迁移到后端或共享包，桌面端只保留本地模式适配

- [x] `npm run build` 零错误
